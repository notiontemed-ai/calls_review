# Контроль звонков — веб-интерфейс

Проверка AI-оценок звонков: сводка дня по группам (Сервис / Продажи / Клиники), список с фильтрами, карточка звонка, вердикты «подтвердить» / «изменить оценку», массовое подтверждение. Авторизация через Битрикс24. Чтение — Google Sheets напрямую, запись — только через n8n.

## Состав

```
public/          фронт-контроллер (index.php) + SPA (index.html, app.js, app.css)
src/             Sheets.php (Google API), Data.php (логика данных), Bitrix.php (OAuth)
n8n/             verdict_webhook.json — workflow записи вердиктов
apps_script/     правки HEADERS и структура журнала
config.example.php
storage/         кеш и логи (должна быть доступна на запись)
```

Требования: PHP 8.2+, расширения curl, openssl, mbstring. Composer не нужен, сборка фронтенда не нужна.

## Развёртывание

1. **Файлы.** Залить проект на сервер. Корень сайта (document root) → каталог `public/`. Все запросы направлять в `public/index.php`:
   - nginx: `try_files $uri /index.php?$query_string;`
   - Apache: `.htaccess` с `FallbackResource /index.php`

   `config.php`, `service-account.json`, `src/`, `storage/` лежат уровнем выше document root и снаружи недоступны.

2. **Google.** В Google Cloud Console создать сервисный аккаунт, включить Sheets API, скачать JSON-ключ → `service-account.json` рядом с config.php. Email аккаунта добавить **читателем** в обе таблицы (основную и журнал 1VwcF6I1…).

3. **Битрикс24.** Разработчикам → Другое → Локальное приложение (серверное). «Путь вашего обработчика» = `https://ваш-домен/auth/callback`. Права (scope): `user`. Полученные client_id/client_secret → в config.php.

4. **config.php.** `cp config.example.php config.php`, заполнить. `storage/` — права на запись для PHP.

5. **n8n.** Импортировать `n8n/verdict_webhook.json`. В ноде Validate заменить SECRET на значение `n8n_webhook_secret` из config.php. В нодах HTTP выбрать существующий credential Google API (тот же, что в основном workflow, но у его сервисного аккаунта должен быть доступ **на запись** к обеим таблицам). Задать переменную окружения n8n `QA_MAIN_SPREADSHEET_ID` = ID основной таблицы (или вписать ID прямо в URL нод). Активировать workflow, URL webhook → `n8n_verdict_webhook_url` в config.php.

6. **Смежное.** Выполнить `apps_script/README_review_columns.md`: 4 колонки в HEADERS + лист «Проверки» в журнале.

## Деплой на nginx

Продакшн работает не на Apache, `.htaccess` nginx не читает — эквивалент лежит в
[`nginx.example.conf`](nginx.example.conf), его применяет администратор в конфиге хостинга
(путь `/internal/calls-review-web/` в файле — плейсхолдер).

Главное требование: **`index.html` должен проходить через `index.php`.** `index.php` подставляет
`?v=<filemtime>` к `app.css` и `app.js` и отдаёт html с `Cache-Control: no-cache`, а сама статика
отдаётся с `max-age=31536000, immutable`. Так после деплоя браузер гарантированно берёт свежий
`app.js`, а не старый из кеша.

Если статику отдаёт nginx напрямую (текущая ситуация) — версии `?v=` всё равно работают: меняется
URL файла, поэтому ни кеш браузера, ни DDoS-Guard не мешают. Достаточно, чтобы `index.html`
не отдавался напрямую.

## Проверка

1. `https://домен/` → «Войти через Битрикс24» → после логина видна сводка.
2. Вкладка «Звонки»: фильтры и пресеты работают, карточка открывается, тяжёлые поля грузятся только при открытии.
3. В карточке непроверенного звонка «Подтвердить оценку» → в журнале появилась строка, в основном листе заполнились `review_*`, статус в списке сменился.
4. «Изменить оценку» без комментария → ошибка валидации; с комментарием → в списке новая оценка с зачёркнутой старой.
5. Выделить несколько → «Подтвердить оценки» → сводка результата, уже проверенные пропущены.
6. Повторный вердикт по проверенному звонку невозможен (кнопок нет; API вернёт ALREADY_REVIEWED).

## Заметки

- Кеш чтения Sheets — 45 сек (`cache_ttl_sec`); после записи вердиктов кеш сбрасывается автоматически.
- Ошибка n8n → пользователю «Запись вердиктов не выполнена», вердикт не считается проставленным.
- Логи: `storage/app.log` (входы, вердикты, ошибки).
- При росте объёмов слой чтения (`src/Sheets.php` + `src/Data.php`) заменяется на локальную реплику без изменения API и фронтенда.
